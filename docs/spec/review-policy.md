# 出題ポリシー v1

`GET /api/review/next` が「次の 1 枚」を選ぶ規則。core の SQL(`next_card_query`)はこの文書だけを正とする。

## 対象

- 段: 初級・中級・上級・統合
- 有効なカードだけ: `retired_at IS NULL` かつ、ノートが未削除

## 1 日

- 「1 日」は `study_day_start`(JST 04:00 始まり)で切る。新規枠・兄弟・統計のすべてで同じ境界を使う

## 候補

1. **復習**: `fsrs_state = 'review'` かつ `due_at <= now`。段を問わず、解禁状態とも無関係に出す
2. **新規**: `fsrs_state = 'new'` で、今日の新規導入数が枠未満、かつ段の解禁を満たす

## 段の解禁(新規の導入にだけ効く)

- **中級**: そのノートの有効な初級カードが、すべて `stability >= 7` 日。初級カードが 1 枚も無いノートは解禁済みとみなす
- **上級**: 中級が解禁済み、かつそのノートの有効な中級カードが、すべて `stability >= 21` 日。中級カードが無ければ中級の解禁条件だけで足りる
- 未学習(`stability` が NULL)のカードは条件を満たさない
- 一度導入したカードの復習は、あとで解禁条件を割り込んでも止めない(FSRS の間隔を崩さないため)

## 統合の解禁(新規の導入にだけ効く)

- 自ノートと参照先の**すべての**ノートで、上級の解禁条件(初級がすべて `stability >= 7`、かつ中級がすべて `stability >= 21`)を満たすときだけ出す
- 参照先のノートが存在しない・削除済みなら出さない
- 導入済みの統合カードの復習は、ほかの段と同じく解禁と無関係に出す

## 新規枠

- 1 日 5 枚。段をまたいだ合計
- 数え方: 初回の review が今日の学習日内にあるカードの枚数(reviews は追記のみなので、最初の行が導入日)
- 期限の来た復習は枠に含めない

## 兄弟(同一ノート)

- 今日すでに review したカードがあるノートの、**他の**カードは今日は出さない
- 同じカード自身の再出題(Again のあとに再び期限が来た等)は妨げない
- 統合カードは自ノートのカードとして扱う(参照先ノートの兄弟にはしない)

## 交互配置

- 分類 = `major / middle / minor` の 3 つ組(小分類名だけでは比べない)
- 直前の問題(最後の review)と同じ分類のカードは、ほかの分類の候補があれば後回しにする。同じ分類しか残っていなければ出す
- 統合カードの分類は自ノートの分類(参照先は同一小分類なので一致する)

## 並び順(上が優先)

1. 直前の問題と違う分類
2. 復習 → 新規
3. 復習は `due_at` が古い順、新規は `created_at` が古い順
4. `stable_key`

## 定数(core の 1 か所で定義する)

| 名前 | 値 |
|---|---|
| `NEW_CARDS_PER_DAY` | 5 |
| `UNLOCK_INTERMEDIATE_DAYS` | 7.0 |
| `UNLOCK_ADVANCED_DAYS` | 21.0 |
